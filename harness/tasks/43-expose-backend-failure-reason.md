# Task 43: 백엔드 실패 사유 노출 — 고정 문구 덮어쓰기 제거

> 구현 절차·검증은 `PLAN.md` 참고.

## 배경

Server Action 29곳이 백엔드가 준 실패 사유를 받아놓고 **고정 문구로 덮어쓴다.**

```ts
catch (error) {
  if (isRedirectError(error)) throw error;
  return { success: false as const, message: "Flag 삭제에 실패했습니다." };
  //                                          ↑ 왜 실패했는지가 사라진다
}
```

사용자는 이유를 알 수 없고, 문의가 들어와도 재현할 수 없다.
백엔드는 이미 표시용 한국어 문장을 주고 있는데(`"모집 기간이 지난 깃발입니다."`)
프론트가 문 앞에서 버리는 구조다.

Task 41에서 같은 성격의 2곳(`leaveAction`, `acceptInvitationAction`)을 고쳐
실제로 사유가 화면에 뜨는 것을 확인했다. 이 태스크는 나머지에 같은 처리를 한다.

## 왜 지금인가 — Task 42 다음이어야 했다

이 작업은 기술적으로는 42 없이도 가능했다. 그러나 **그 순서로 했으면 안 됐다.**

42 이전에는 `error.message`가 서버 문장일 수도, `fetch failed` 같은 JS 런타임
문자열일 수도 있었다. 그 상태에서 통과 범위를 넓혔다면 영문 내부 문자열 노출 지점을
**20곳에서 49곳으로 늘리는** 작업이 됐다.

42가 세운 불변식(`ApiError.message`는 언제나 보여도 되는 문장) 위에서만
이 변경이 안전하다. 5xx·네트워크·파싱 실패는 이미 FE 고정 문구로 치환되므로,
통과시켜도 사용자에게 도달하는 것은 4xx의 서버 문장뿐이다.

## 대상

| 파일 | 곳수 |
|---|---|
| `buzz.ts` | 7 |
| `flag.ts` | 8 |
| `profile.ts` · `label.ts` | 3 · 3 |
| `friendRequest.ts` · `friendship.ts` · `notification.ts` · `social.ts` | 2씩 |

이 중 **12곳은 조회(GET) 실패**로 `"...불러오는 데 실패했습니다"` 형태다.
페이지가 그 `message`를 렌더링하지 않는 경우가 많아 체감 효과는 낮지만,
파일 안에서 처리 형태를 통일하는 편이 다음 사람이 읽기 쉽다. 전부 동일하게 바꾼다.

체감 효과는 **나머지 17곳(변경 요청)** 에서 나온다 — 삭제·수정·초대·권한 변경 등
사용자가 버튼을 눌러 실패를 직접 마주하는 지점들이다.

## 범위

### 포함

- 29곳을 `error instanceof Error ? error.message : "<기존 문구>"` 형태로 통일
- 기존 고정 문구는 **fallback으로 유지**한다(`ApiError`가 아닌 예외가 올라올 경우)

### 제외

| 항목 | 이유 |
|---|---|
| 조회 실패 시 빈 배열 반환 15곳 | **Task 44.** "실패"와 "데이터 없음" 구분은 `kind`와 화면 설계가 필요하다 |
| 409 → 재조회 | **Task 45.** 문구가 아니라 동작 변경 |
| `validation` 필드 바인딩 | **Task 46.** 폼 UI 변경 |
| 컴포넌트 쪽 fallback 문구 | 그대로 둔다. `result.message ?? "기본 문구"` 구조 유지 |

## 리스크

**백엔드 문구가 그대로 사용자에게 도달하는 범위가 29곳 늘어난다.**
4xx 문구는 표시용 한국어임을 실측으로 확인했지만(Task 41·42),
확인된 것은 일부 엔드포인트다. 아직 보지 못한 4xx 문구가 어색하거나
내부 용어를 담고 있을 수 있다.

완화책은 둘이다 — 42가 5xx·네트워크를 이미 막고 있고,
검증에서 도메인별로 실제 실패를 한 번씩 일으켜 문구를 눈으로 확인한다.

## 완료 기준

- 29곳이 백엔드 사유를 통과시킨다
- 각 도메인에서 실제 실패를 일으켰을 때 화면 문구가 사람이 읽을 수 있는 한국어다
- 백엔드가 꺼진 상태에서는 여전히 FE 고정 문구가 뜬다 (42의 불변식 유지)
